Neural Network)을 학습시키고, 그 추정치를 실제 비행 제어 루프에 연결해서 효과를 검증하는

## 요약

PID만으로도 위치오차는 잡히지만(강풍 8.5m/s에서도 <5cm) 기체가 계속 기울어진 채
유지됨 — 이 기울기(바람 반응)를 PINN으로 추정해서 가속도/토크 피드포워드로 앞서
보정하는 게 목표. 시행착오 과정 자체가 이 프로젝트의 핵심 내용이라 자세한 서사는
[CAPSTONE_REPORT_DRAFT.md](CAPSTONE_REPORT_DRAFT.md)에 정리해뒀고, 여기는 결과만:

- **병진(위치) 보정**: position setpoint 보정은 발산(1차 실패) → 가속도만 얹는
  구조로 성공 → 5조건 A/B 5/5 개선, gust 포함해도 4/4 개선
- **회전(자세) 보정**: 실시간 폐루프 발산(모델이 자기 입력을 미분해 돌려주는
  지름길을 학습) → 데이터 수집 중 무작위 토크 주입(더더링)으로 지름길 봉쇄 →
  발산 해소, "첫 순이익"(3/5 개선)처럼 보였으나 그건 1회 측정이었음 → N=10
  재검증하니 뒤집힘 → gain 재스윕(0.05~0.30)해도 5조건 전부 만족하는 값을
  못 찾음 — **현재 미해결, 배포 안 함**
- **gust 추정 "구조적 한계"로 오판했던 것**: 실제 원인은 yaw(기수 방향) 범위가
  좁은 데이터였음 — yaw 그리드로 재수집해서 5배 개선
- **재현성 인프라**: 1회 측정 A/B는 노이즈에 묻힘 → 5회 반복 인프라 구축 →
  안정화 대기시간 부족이 근본 원인이었음을 확정
- **더더링 의존성 발견**: 배포 모델이 학습 때 쓴 더더링 자이로 신호 통계에
  암묵적으로 의존 → 실비행(더더링 없음)에서 추정이 깨짐 → 더더링/비더더링 혼합
  재학습으로 해결

## 결과 하이라이트

| 실험 | 지표 | 결과 |
|---|---|---|
| PID-only 베이스라인 (강풍 8.5m/s) | 정상상태 위치오차 | <5cm |
| PINN 바람 추정 (gust 포함, yaw 그리드, 5-fold) | 풍속 MAE | **0.355 ± 0.018 m/s** |
| yaw 일반화 검증 (학습 밖 각도) | wind_vx/vy MAE | 0.229 / 0.241 m/s |
| PINN 위치보정 ON/OFF (5조건, N=10 재검증) | 피크 위치오차 개선율 | calm 제외 4/4 개선 (+1.9%~+14.3%) |
| PINN 위치보정 ON/OFF (gust 4조건, N=10 재검증) | 피크 위치오차 개선율 | 4/4 중립 (배포 안 함) |
| 비더더링(실비행 조건) 고정바람 추정 | 풍속 MAE | 1.37→**0.18~0.43 m/s** (혼합 재학습 후) |
| PX4 토크 피드포워드 A/B (5조건, N=10, gain 재스윕 후 최선값) | 자세 피크 편차 개선율 | 5/5 방향 개선됐으나 default 여전히 손해 — **미해결, 배포 안 함** |

## 다음으로 할 만한 것

**432조건 재학습 모델 — 최종 결론: 배포 안 함.** 오프라인 gust 추정 정확도는
20% 개선(MAE 1.517→1.218m/s)됐지만, SITL A/B를 4개 gust 조건 전부 10회씩
반복측정한 결과 **개선율이 전부 중립**(light -4.7%±17.2%, default +1.6%±10.9%,
crosswind +0.8%±6.9%, strong +1.0%±2.1%). 처음 5회 반복 때 나왔던 두 극단
(crosswind 심한 악화, strong 확실한 개선)은 둘 다 재현 안 됨 — N=5는 이런
A/B에 표본이 부족했던 것으로 결론. 원본(12-30절) 모델 유지, 오프라인 정확도와
실제 제어 효과는 별개라는 교훈만 다시 확인됨(EXPERIMENTS.md 12-35~39절).

**`TAU_FF_GAIN` 물리 단위 캘리브레이션도 완료 — 계산은 성공, 적용은 안 함.**
더더링 학습 데이터(알려진 크기의 토크를 주입하며 로터 반응을 같이 로깅해둔 것)로
회귀해서 진짜 N·m↔정규화 변환배율을 계산(roll 3.90/pitch 6.30/yaw 4.20, 기존
0.2의 약 20배). SITL에서 그 근처 값(1.0)을 조심스럽게 테스트해보니 이미 확실히
발산(자세오차 -95.0%) — 추정 노이즈가 게인만큼 증폭되는 게 원인으로 보여 기존
0.2 그대로 유지. "왜 0.2가 물리값보다 훨씬 작아야 했는지"를 정량적으로 설명한
것으로 의미를 둠(EXPERIMENTS.md 12-40절).

**회전 피드포워드 "첫 순이익"도 N=10 재검증에서 뒤집힘 — 재스윕으로도 못 고침.**
병진/회전 5조건 A/B를 전부 N=10으로 재검증(EXPERIMENTS.md 12-41절)했더니, 병진은
방향 유지(strong의 "+38.2%"는 1회 측정의 과대추정, 실제 +3.0%±5.1%)였지만
**회전은 부호 자체가 뒤집힘**(default -7.9%±3.5%, strong -3.6%±3.4%). `TAU_FF_GAIN`을
현재 모델 기준으로 재스윕(0.05~0.30, 12-42절)해봤지만 **5조건 전부를 만족하는
값이 없었다** — 가장 나은 0.10도 gain=0.20 대비 5개 조건 전부 방향은 개선됐지만
default는 여전히 확실한 손해(-3.1%±2.8%). 회전 피드포워드는 게인 튜닝만으로는
안 풀리는 것으로 보이며, **현재 미해결 상태로 배포 보류**.

**correction_experiments 텔레메트리/오프보드 진입부 보일러플레이트 정리도 완료.**
4개 스크립트에 복붙돼있던 "연결·GPS확인, arm+이륙, pv/att/gyro 모니터, 초기
offboard 진입" 블록을 `correction_common.py`로 통합(4개 파일 총 328줄 삭제) —
SITL에서 회전/병진 스크립트 각 1회씩 완주시켜 동작 동일함 확인. 실제 가속도/토크를
흘려보내는 송신 루프 자체는 스크립트마다 달라 그대로 둠(EXPERIMENTS.md 12-43절).

**tau 추정치 EMA 스무딩 — N=10 재검증에서 약한 개선 신호 확인, 확정은 아님.**
병진처럼 회전도 게인 곱하기 전에 스무딩을 넣는 기능을 추가(EXPERIMENTS.md
12-44절). 첫 N=3 프로브는 판단 불가였지만(N=3이 이 노이즈 수준을 구분하기엔
부족), N=10으로 정식 재검증하니 tau_smooth_s=0.2에서 `default` 조건이
-3.1%±2.8%(확실한 손해)→+0.5%±3.8%(중립)로 바뀜 — "확실한 손해"는 없어졌지만
"확실한 순이익"이라 부르기엔 CI가 아직 넓음(12-45절). 5조건 전체 검증은
사용자 승인 대기 중.

**남은 것(우선순위순)**:
1. tau_smooth_s=0.2를 5조건 전체 N=10으로 검증 — 지금까지 양호했던 조건들을
   스무딩이 훼손하지 않는지 확인 (EXPERIMENTS.md 12-45)
2. 실제 하드웨어(Jetson) 이관 — 펌웨어 재빌드 → 지상 통신/모터 재캘리브레이션 →
   계류비행 → 자유비행 순
3. 캡스톤 보고서 그래프/표 시각화(텍스트 초안은 완료)

**완료된 것 전체 목록**은 [EXPERIMENTS.md](EXPERIMENTS.md) 맨 아래 "다음 단계" 절 참고.
