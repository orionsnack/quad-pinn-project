공학 설계 프로젝트. PX4 SITL(Gazebo) 환경에서 바람 외란을 추정하는 PINN(Physics-Informed
Neural Network)을 학습시키고, 그 추정치를 실제 비행 제어 루프에 연결해서 효과를 검증하는
프로젝트입니다.

## 지금까지 한 것 (요약)

### 1. 시뮬레이션 환경 구축 & 기본 버그 해결
PX4 SITL + Gazebo(Harmonic) + MAVSDK-Python 환경을 구축하고, Offboard 제어 스크립트들을
만드는 과정에서 발견한 버그들을 해결했습니다.
- **yaw rate 명령이 비결정적으로 동작하던 버그**: 이륙 후 목표 고도 도달을 확인 안 하고
  바로 Offboard로 넘어가서, 지면 근처에 낮게 고정된 채로 yaw 명령이 무시되던 문제였음.
  `telemetry.position()`으로 실제 고도 도달을 확인한 후 Offboard 전환하도록 수정함.

### 2. 바람 외란 PID-only 베이스라인
`gz_x500_windy` 월드에서 순수 PID 컨트롤러가 바람에 얼마나 잘 버티는지 측정. 강풍
(8.5m/s)에서도 위치 오차는 5cm 이내로 거의 완벽히 잡지만, 그 대가로 roll/pitch가
바람 세기에 비례해서 계속 기울어진 채 유지됨 — 이게 PINN이 추정할 대상.

### 3. PINN 바람 추정 모델
드론의 최근 상태(수평속도, roll, pitch)만 보고 현재 바람 벡터를 추정하는 작은 신경망을
학습. 지도학습 loss + 물리 법칙(항력 방정식) 기반 loss를 함께 사용.
- **고정바람 조건(40개)만으로 학습**했을 때: 풍속 추정 오차 **0.37~0.5 m/s** (평균
  풍속 4.6m/s 대비 약 10%) — 꽤 정확함
- **시간에 따라 변하는 바람(gust)까지 포함**해서 재학습했을 때: 오차 **1.8 m/s**로
  뚜렷이 악화. 모델 크기 키우기, 정규화, 데이터 추가, 강풍 데이터 보강 등 여러 방향을
  시도했지만 못 뚫음. 5-fold 교차검증으로 재확인해도 결과는 동일 → 당시엔 **모델
  구조(작은 MLP + 최근 1초 히스토리)의 한계**로 잠정 결론했었으나, **이 결론은
  나중에 뒤집힘** — yaw 그리드로 gust 데이터를 재수집하니 오차가 **0.36 m/s로
  5배 개선**됨(아래 5절 참고). 진짜 원인은 모델 구조가 아니라 좁은 yaw 범위
  데이터였음.

### 4. 추정치를 실제 제어에 연결
- **1차 시도(실패)**: 추정 바람만큼 목표 위치(position setpoint)를 반대로 밀어주는
  방식 → 보정이 setpoint를 계속 흔들면서 폐루프 발산(roll 수십도까지) 발생. "PID가
  이미 자세 트림만으로 위치오차를 거의 다 잡고 있어서 위치 보정이 애초에 안 맞는
  지렛대"였다는 걸 알게 됨.
- **2차 시도(성공)**: 목표 위치는 절대 안 흔들고, 추정 바람 반대방향으로 **가속도만
  추가로 얹어 보내는 방식**(`set_position_velocity_acceleration_ned`)으로 구조 변경.
  강풍 온셋 시 피크 위치오차가 **0.47m → 0.21m로 약 55% 감소**.
- 5개 바람 조건(무풍/약함/보통/강함/옆바람)에서 A/B 반복 검증, deadband(무풍일 때
  보정 끄기) 추가 후 **5개 조건 전부 개선**(+8.2%~+71.3%).
- **gust 조건으로 확장 검증**: 위 검증은 전부 고정바람 기준이었는데, 바람이 사인파로
  계속 출렁이는 gust 조건 4개(약함/보통/강함/옆바람 방향, 진폭 ±60%, 주기 6초)에서도
  같은 A/B를 돌려봄. gust 풍속 추정 자체가 부정확(3절 참고, MAE 1.8m/s)함에도
  **4개 중 3개 조건 개선**(보통 +33.6%, 강함 +23.5%, 옆바람 +29.7%), 약한 gust만
  소폭 악화(-5.3%) — 상세 기록은 EXPERIMENTS.md 12-7절 참고.
- **`ACCEL_GAIN`/`WIND_DEADBAND_MPS` 체계적 튜닝 시도**: 약한 gust 문제를 겨냥해
  deadband를 낮추고 gain을 올려봤으나, 전체 조건으로 재검증하니 강풍 조건은 좋아지는
  대신 무풍/약풍 조건이 그만큼 나빠지는 트레이드오프만 확인됨. **원래 손으로 정한 값
  (0.15/1.0)이 전체 조건 기준으로는 이미 가장 균형 잡힌 선택**이라는 결론 — 상세
  기록은 EXPERIMENTS.md 12-8절 참고.
- **yaw 그리드로 재학습한 새 모델로 재검증**: fixed-wind A/B 4/5 조건, gust A/B 4/4
  조건 개선 유지 확인 (EXPERIMENTS.md 12-12/12-13절).

### 5. 회전 방해토크(τ_disturbance) 확장 — 발산 해결 후 첫 순이익 달성
세미나 원래 과제(`Jω̇=τ_motor+τ_disturbance`를 PX4 기존 PID에 피드포워드로 얹기)를
병진 항력 추정과 결합. 회전 쪽은 정답 라벨이 따로 없고 텔레메트리에서 물리잔차로
바로 구해지므로, 그 잔차 자체가 학습 신호가 되는 구조.
- 데이터 수집 스크립트에 자이로/액추에이터 로깅 추가, 15세션(2700조건) yaw 그리드
  재수집 + 결합 학습 + 5-fold 교차검증까지 **오프라인은 성공**(회전 물리잔차
  0.763±0.238 rad/s²). PX4 펌웨어(`mc_rate_control.cpp`)에 MAVLink DEBUG_VECT
  기반 토크 피드포워드 채널을 새로 구현·캘리브레이션 검증(정상 작동 확인).
- 실시간 A/B 1차 시도에서 **폐루프 발산**(무풍에서도 21°+) — 원인은 모델 입력
  피처에 각속도(wx/wy/wz)가 포함되어 있어 보정이 자기 자신의 입력을 오염시키는
  양성 피드백. 이후 게인 스윕(튜닝으로 해결 불가 확정)과 저역통과 필터 재도입
  (오히려 더 심하게 발산, 38.7°)도 둘 다 실패.
- **근본 원인 재진단**: 회전 물리손실은 모델 출력이 물리식을 만족하는지만 볼 뿐,
  액추에이터 정보가 모델 입력엔 없어서 인과적 추론을 강제하지 않음 — 모든 학습
  데이터가 무보정 상태로만 모여있었기 때문에, 네트워크가 "자기 입력(각속도)을
  그냥 미분해서 돌려주는" 지름길을 학습해버린 게 발산의 진짜 원인이었음.
- **해결책**: 데이터 수집 중에 실제로 무작위 토크를 주입(더더링, 개루프라
  발산 위험 없음)해서 이 지름길 자체를 데이터로 봉쇄. 15세션(2700+조건) 재수집
  + 재학습 + SITL A/B 재검증 결과 **발산이 완전히 사라지고, default/strong
  조건이 사실상 중립(-2.7%/-5.8%)까지 도달**(초기 시도 대비 손해 10배 이상 감소).
- **`TAU_FF_GAIN` 재스윕으로 첫 순이익 달성**: 더더링 이전엔 게인 튜닝이 막힌
  방향이었지만(추정치 품질 자체가 나빴음), 더더링으로 추정치가 좋아진 이 모델로
  다시 스윕해보니 gain=1.0→0.2로 낮추면서 부호가 바뀜.
- **5조건(병진 A/B와 동일한 calm/light/default/strong/crosswind)으로 확장
  검증**: 5개 중 3개(default/strong/crosswind) 개선(+1.0%~+5.5%), 무풍/약풍만
  미세한 손해(절대오차 0.08~0.10°) — **병진 A/B(4/5 조건 개선)와 거의 같은
  패턴**으로 재현성 확인.
- **yaw 일반화 검증**: 스폰 yaw에서 180도로 회전시켜도 default/strong 둘 다
  개선 방향 유지(strong은 +5.0%로 오히려 더 좋음) — gain=0.2가 특정 yaw
  우연이 아님을 확인. 세미나 원 과제(회전 방해토크 실시간 피드포워드)가
  실제로 작동하고 도움이 되는 첫 사례로 정리됨. 상세 기록은 EXPERIMENTS.md
  12-16/12-17절 참고. 병진 쪽 성과(위 4절)는 이 실험과 무관하게 그대로 유효함.

### 6. gust 정확도 "구조적 한계" 결론이 틀렸음을 확인 — yaw 그리드로 5배 개선
3절의 gust MAE 1.8m/s 벽은 "모델 구조 자체의 한계"로 잠정 결론했었지만, 그건
yaw 그리드 수정(위 3/5절) 이전, 좁은 yaw 범위로만 모은 gust 데이터 기준이었음 —
실제로 yaw 그리드로 gust를 재수집해본 적은 없었음. 병진 고정바람과 회전 둘 다
같은 원인(yaw 다양성 부족)이었던 전례가 있어 재검토함.
- `wind_gust_sweep.py` 기본값(12yaw×5조건, ~25분)으로 재수집 + 기존 더더링
  고정바람 데이터와 합쳐 5-fold 재학습 결과 **speed MAE가 1.794±0.520 →
  0.355±0.018 m/s로 5배 개선**, fold별 편차도 훨씬 안정적으로 줄어듦.
- 회전 성능은 유지됨(물리잔차 3.02, gust 없이 학습했을 때와 거의 동일). 이
  새 체크포인트로 회전 피드포워드(gain=0.2)도 재검증 — default +2.1%, strong
  +1.7%로 여전히 순이익, 문제없어 그대로 배포함.
- **gust A/B(병진 피드포워드 보정)도 이 체크포인트로 3차 재검증**: 4/4 조건
  전부 개선, 그것도 이전 두 버전보다 가장 큰 폭(light_gust +9.4%, default
  +53.8%, strong +51.8%, crosswind +60.5%) — 계속 골칫거리였던 light_gust까지
  확실한 개선 구간으로 들어옴.
- **결론**: 병진 고정바람(3절), 회전(5절), gust(이 절) 세 가지 문제 전부 진짜
  원인이 "모델 구조 한계"가 아니라 "좁은 yaw 범위 데이터"였다는 게 이 프로젝트
  전체를 관통하는 패턴으로 확인됨. 상세 기록은 EXPERIMENTS.md 12-18/12-19절 참고.

```
  wind_gust_TIMESTAMP_yaw..._seed.../     gust 수집 1회분 격자 PNG
```

  캘리브레이션 완료. 게인 스윕/저역통과 필터는 둘 다 실패로 결론 남. **근본
  원인(무보정 데이터로 인한 자기입력 미분 지름길) 재진단 후 토크 더더링으로
  데이터 재수집(15세션) + 재학습 + 재검증 — 발산 완전히 해소. 이 새 모델로
  게인 재스윕(gain=0.2)해서 순이익 달성, 병진 A/B와 동일한 표준 5조건으로
  재검증한 결과 5개 중 3개 개선(+1.0~5.5%)으로 병진과 거의 같은 패턴 확인,
